# H12. 최빈값 필터의 최적 창이 EXP-019가 쓴 k=9인가

## 질문

EXP-019는 레벨 예측을 파일 순서를 따라 최빈값 필터로 평활해 LB 3.1199 → **3.0493**을 얻었고,
창 `k=9` **하나만** 측정했다. 그 선택은 real을 test보다 잘게 쪼갠 배열에서 k=9가 0.9975,
k=31이 0.9897(경계 손상)이라는 관측에 근거했지만, **k=9 주변은 보지 않았다.**

`k ∈ {3, 5, 7, 9, 11}`을 같은 조건에서 나란히 재면 9가 실제로 최적인가, 아니면 이웃 창이
더 나은가.

## 조건

- **X**: real train SEM 60,664장의 레벨 사후확률. `scripts/dump_level_proba.py`가 EXP-013
  CNN(`runtime/ckpt/EXP-013-level-cnn.pt`)으로 한 번 덤프한 것을 읽기만 한다. 모든 arm이
  **같은 덤프**를 쓴다 — 다른 덤프를 읽으면 비교가 성립하지 않는다.
- **y**: 폴더명 `Depth_{110,120,130,140}`(주최측 실측 라벨, `real_group_label`).
- **지표**: `sem.site_split`의 사이트 단위 홀드아웃 정확도(val_frac 0.2, seed 0).
  사이트 단위인 이유는 사이트당 crop ~31장이 라벨을 공유해 이미지 단위 split이 낙관 편향되기 때문.
- **런 구조**: test는 파일 순서가 곧 내용 순서라 런이 생기지만 real train은 그렇지 않다.
  그래서 사이트 id를 시드로 섞어 이어붙여 런을 만든다(`build_run_order`). 결과의 `run_count`를
  test의 런 1,046개와 나란히 적는다.
- **실행**: `scripts/sweep_level_smoothing.py --arm smooth --values 3,5,7,9,11`. GPU 불필요.

## 무엇이 답인가

**읽는 것은 arm 사이의 순위이지 절대 정확도가 아니다.** 사후확률은 real train으로 학습된
분류기가 real train에 낸 **in-sample** 예측이라 절대값이 낙관 편향돼 있다. 두 arm이 같은
편향을 공유하므로 순위만 의미가 있다.

- **채택 권고**: k=9가 아닌 창이 홀드아웃 정확도에서 **명확히** 앞서고, 그 차이가 인접 창들
  사이의 변동폭보다 크다. 이 경우에도 리더보드 판정은 별도이며 여기서 내리지 않는다.
- **조건부**: 순위는 갈리지만 차이가 인접 변동폭 안이다 → 창 축은 이미 포화. 리더보드 슬롯을
  쓸 근거가 없다.
- **결론 없음**: 위 둘로 읽히지 않으면 그렇게 적고 밴드를 함께 남긴다. "무해하다"로 읽지 않는다.

**돌리지 않을 조건**: `run_count`가 test의 1,046과 자릿수가 다르면 런 길이 분포가 달라
최적 k가 옮겨가지 않는다 — 그 경우 수치를 판정에 쓰지 않고 그대로 닫는다.

**제출하지 않는다.** 이 가설은 리더보드 슬롯을 쓰지 않는다. 이 프록시는 과거 두 번 다 낙관이었다
(EXP-013→014에서 2.55pp, EXP-019에서 3.55pp 할인).

## 결과

실행: `scripts/sweep_level_smoothing.py --arm smooth --values 3,5,7,9,11`, seed 0, val_frac 0.2,
입력은 메인 체크아웃 `runtime/cache/real-level-proba.npy` · `real-labels.npy` · `real-site.npy`
(읽기 전용). n = 60,664, 홀드아웃 n = 12,111. 평활 전 홀드아웃 정확도 0.9897.

**`run_count` = 1,550 — test의 런 1,046과 같은 자릿수**(평균 런 길이 60,664/1,550 ≈ 39.1장 대
test 25,988/1,046 ≈ 24.8장). 돌리지 않을 조건에 걸리지 않으므로 수치를 판정에 쓴다.

| report_id | arm | 홀드아웃 정확도 | 변경 장수 | 비고 |
|---|---|---|---|---|
|  | 평활 없음 | 0.9897 | 0 | 기준. 홀드아웃 오답 ≈ 125장 |
|  | smooth k=3 | **0.9995** | 672 (1.11%) | 인접 허용 0.9998. 오답 ≈ 6장 |
|  | smooth k=5 | 0.9991 | 696 (1.15%) | 인접 허용 0.9998. 오답 ≈ 11장 |
|  | smooth k=7 | 0.9988 | 714 (1.18%) | 인접 허용 0.9996. 오답 ≈ 15장 |
|  | smooth k=9 | 0.9987 | 732 (1.21%) | 인접 허용 0.9996. EXP-019의 창. 오답 ≈ 16장 |
|  | smooth k=11 | 0.9986 | 740 (1.22%) | 인접 허용 0.9995. 오답 ≈ 17장 |

오답 장수는 (1 − 정확도) × 12,111로 되돌린 값이다(정확도가 소수 넷째 자리 반올림이라 ±1장).
report_id는 미발급 — 기록소 등록은 코디네이터가 한다.

## 관찰

- **순위는 k에 대해 단조다**: 3 > 5 > 7 > 9 > 11. 인접 창 사이 차이는 0.0004 · 0.0003 · 0.0001 ·
  0.0001이고, k=3과 k=9의 차이는 0.0008(홀드아웃 약 10장)이다. 내부 최적점이 없으므로 "인접
  변동폭"은 잡음 추정이 아니라 추세의 기울기다 — k=3 아래(k=1은 평활 없음 0.9897)가 스윕 경계다.
- **변경 장수도 k에 대해 단조 증가한다**(672 → 740). 창이 넓어질수록 더 바꾸는데 정확도는
  떨어진다 — 추가로 바뀐 장은 교정보다 경계 손상 쪽이다. EXP-019가 k=31에서 본 경계 손상이
  k=3~11 구간에서도 작게 이어진다.
- **이 프록시의 오답 밀도는 test보다 약 4배 낮다.** 평활 전 in-sample 홀드아웃 오답률은 1.03%
  (0.9897)인데, EXP-019가 LB에서 역산한 test의 평활 전 유효 p는 0.9551, 즉 오답률 4.49%다.
  최빈값 필터는 창 안에 오답이 (k−1)/2개 이하일 때만 고친다 — 오답이 드물고 고립돼 있으면 가장
  작은 창으로 충분하고 넓은 창은 경계 손상만 더한다. **오답이 성긴 조건은 그 자체로 작은 k를
  편애한다.** 즉 in-sample 편향은 arm 사이에 공유되는 상수가 아니라 k와 상호작용한다.
- 런 구조는 비교 가능한 범위다(1,550 대 1,046, 평균 런 길이 ~39 대 ~25). 다만 test의 런이 더
  짧다는 방향은 위 효과와 같은 쪽(작은 k 편애)이어서, 런 구조 차이는 오답 밀도 효과를 상쇄하지
  않는다.
- 이 덤프의 평활 전 정확도(0.9897)와 k=9 값(0.9987)은 EXP-019 당시 프록시(런 2,836,
  0.9806 → 0.9975)와 다르다 — 런 수가 다른 별개 구성이므로 두 값을 나란히 비교하지 않는다.

## 판정 · 미검증

**판정**: **결론 없음.** 수치만 보면 k=3이 k=9를 0.0008(약 10장) 앞서고 이는 인접 창 차이
(최대 0.0004)보다 커서 「채택 권고」의 문구를 충족한다. 그러나 「무엇이 답인가」가 순위를 읽을 수
있다고 한 근거 — 두 arm이 같은 in-sample 편향을 공유한다 — 가 이 축에서는 성립하지 않는다.
in-sample 오답 밀도(1.03%)가 test(4.49%)보다 약 4배 낮고, 오답 밀도는 최적 창을 직접 옮기는
변수이며, 그 편향의 방향이 정확히 관측된 순위(작은 k 우위)와 같다. 따라서 "k=3이 test에서도
k=9보다 낫다"로 읽을 수 없고, "k=9가 최적이다"로도, "창 축은 무해하게 포화됐다"로도 읽지 않는다.
밴드: 홀드아웃 정확도 0.9986~0.9995(k=11~3), 전 구간이 평활 없음 0.9897 대비 +0.89~0.98pp.
리더보드에는 올리지 않았다.

**미검증**:

- test 수준 오답 밀도(~4.5%)에서의 k 순위 — in-sample 사후확률로는 재현되지 않는다. out-of-fold
  사후확률(사이트 단위 K-fold로 분류기를 다시 학습해 덤프)이면 오답 밀도가 test에 가까워질 수 있다.
- seed 간 변동 — seed 0 한 번만 쟀다. 약 10장 차이가 사이트 섞기·홀드아웃 분할 seed를 바꿔도
  유지되는지 모른다.
- 스윕 하한 — k=3이 최소 홀수 창이라 단조 추세의 끝이 곧 최적인지, 경계 손상이 k=3에서 얼마인지는 따로 재지 않았다.
- 리더보드에서의 순위 — 이 프록시는 과거 두 번 모두 낙관이었다(2.55pp, 3.55pp 할인).

## 이관 범위

**이 수치는 레벨 축 어디에도 이관되지 않는다.** 판정이 "결론 없음"인 이유가 곧 이관을 막는
이유다 — 사전등록이 "두 arm이 같은 in-sample 편향을 공유하므로 순위는 유효하다"를 전제했는데,
편향은 상수 오프셋이 아니라 **오류 밀도**를 바꾼다(in-sample 1.03% 대 test 4.49%). 오류가
희박할수록 작은 창이 유리하므로 최적 k 자체가 이동한다. k=3이 앞선 것은 프록시의 성질이지
test에 대한 주장이 아니다.

**얻은 것은 방법론이다.** 이 프록시로 창 크기를 고르지 마라 — 그러려면 오류 밀도를 test에
맞춘 out-of-fold 사후확률이 필요하다. `hypotheses.md`의 레벨 축 후보를 평가할 때 이 제약을
함께 읽을 것.
