# 추론 단계 분리 — CPU 후처리 가설의 병렬 실행

> 2026-09-13 · 브랜치 `feature/split-infer-stages`
> 레퍼런스: `custflow-pipeline/.agents/rules/git-workflow.md` (워크트리 병행 운용 선례)
> 함께 쓰인 문서: `2026-09-13-wandb-registry-design.md` (기록소 전환 — **다음 사이클**)

## 1. 무엇을 하려는가

여러 가설을 동시에 진행하고 싶은데, 지금은 **GPU를 쓰지 않는 가설조차 직렬화된다.**

`--level-smooth`, `--level-hmm`, `--tau`, `--histmatch` 는 전부 `scripts/infer_decomposed.py`의
`main()` 안에 있고, 그 스크립트는 torch를 import하는 GPU 경로다. 그래서 최빈값 필터의 창 크기
하나를 바꾸려 해도 구조 회귀기 추론을 통째로 다시 돌려야 한다. EXP-019가 `k=9` 하나만 측정하고
신기록(LB 3.0493)을 낸 뒤 `k∈{3,5,7,11}`을 나란히 보지 못한 이유가 이것이다.

그런데 `main()`의 데이터 흐름은 이미 깨끗하게 갈라져 있다:

| 단계 | 결정하는 인자 | 근거 |
|---|---|---|
| **GPU** | `--ckpt` `--arch` `--width` `--histmatch` `--adabn*` | 전부 `sp = model(x)`, 즉 ŝ에 영향 |
| **CPU** | `--tau` `--level-source` `--level-smooth` `--level-hmm*` | ŝ를 **읽기만** 하고 `cls` 벡터와 조립에만 영향 |

`reconstruct_and_zip`의 루프에서 `sp = model(x)` 이후는 전부 배열 연산이다. τ 클램프도 `sp`에
걸리는 CPU 가능 연산이고, `lv`는 `cls`에서만 나온다.

**목표 하나**: ŝ를 한 번 뽑아 두고, CPU 후처리 가설을 워크트리에서 병렬로 돌린다.

실험 운영의 **순서**(선보고 → 레지스트리 → 제출)와 저장 형식은 그대로 둔다. 병렬 실행이
강제하는 두 가지만 바뀐다: 기록의 **주체**가 코디네이터로 고정되고(§3.4), 레코드에 소스
브랜치/커밋이 optional 필드로 붙는다(§3.5). 기록소 자체의 교체는 이 범위 밖이다(§9).

이 설계는 코드가 이미 요청해 둔 것이기도 하다 — `viterbi_levels`의 독스트링은 자기전이 확률
`a`에 대해 "실측이 아니라 **실험이 스윕할 하이퍼파라미터**이므로 플래그로 노출한다"고 적는다.

## 2. 두 개의 아티팩트와 두 개의 진입점

### 2.1 덤프

- **ŝ 덤프** — `(25988, 72, 48) float32` ≈ **359 MB**.
  float16(180 MB)은 버린다: `d = L·(1−s)`에서 L이 최대 170이라 오차가 ~0.085까지 커져 최종
  `round()`의 경계를 흔든다. 이 저장소는 "지금까지의 레시피가 비트 단위로 재현되어야 한다"를
  코드 주석에 명시하고 있으므로 무손실을 택한다.
- **레벨 사후확률 덤프** — `(25988, 4) float32` ≈ **416 KB**.
  이것이 있어야 `--level-source cnn`(LevelCNN은 torch = GPU)까지 CPU 단계로 넘어온다. 그래야
  `k` · `a` · `τ` · 레벨 소스가 **전부** GPU 없는 탐색 공간이 된다.

### 2.2 진입점

- `scripts/infer_decomposed.py` — 기존 CLI를 **그대로 둔다**. `--dump-structure <path>` 와
  `--dump-level-proba <path>` 를 **추가만** 한다. 기존 호출부의 회귀 위험이 0이어야 한다.
- **새 CPU 전용 진입점** — `(ŝ 덤프, proba 덤프, τ, k 또는 a, 레벨 소스) → 제출 zip + 진단 JSON`.
  torch를 import하지 않는다.
- 조립 로직(`d = L·(1−s)` → clamp → PNG → zip)은 **한 함수로 추출해 양쪽이 같은 코드를 부른다.**
  조립이 두 벌이 되는 순간 두 경로가 갈라지고, 그때 어느 쪽이 과거 점수를 낸 경로인지 말할 수
  없게 된다.

### 2.3 조립은 numpy + stdlib만 쓴다 (cv2 제거)

패키지 본 의존성은 `numpy` · `httpx` · `pyyaml` 뿐이고 **`opencv-python`은 `baseline` 그룹**이다
(torch와 같은 그룹). 워크트리는 dev 그룹만 sync하므로 **cv2도 torch도 없다.** 따라서 CPU
진입점은 cv2를 쓸 수 없고, §2.2가 조립 함수의 단일화를 요구하므로 인코더를 둘로 나눌 수도 없다.

결론: **양쪽 모두 stdlib(zlib) 기반 8bit 그레이 PNG 인코더를 쓰고, `infer_decomposed`에서
`cv2.imwrite`와 `import cv2`를 제거한다.** 이것은 `submission.py`가 디코더에서 이미 세운 전례와
같은 논리다 — "cv2는 `baseline` 그룹이라 기본 환경에 없을 수 있는데, 제출 직전 검증이 옵션
의존성 때문에 건너뛰어지면 검증이 없는 것과 같다". 기존 `decode_png_gray8`이 PNG 필터 5종을
모두 복원하므로 새 인코더의 출력을 읽는 데 문제가 없다.

**딸린 결과**: 새 경로가 만드는 zip은 **과거 zip과 바이트가 다르다**(픽셀은 같다). 채점은
픽셀로 하므로 점수에는 영향이 없다. §6의 증거 설계가 이 사실을 반영한다.

## 3. 워크트리 병렬 실행과 읽기 전용 공유

### 3.1 입력은 명시적 경로 인자로만

CPU 진입점은 `--structure` / `--level-proba` 를 **필수 인자**로 받고 기본값을 두지 않는다.

- `config.py::project_root()` 는 `__file__` 기준이므로 워크트리에서 상대 기본값은 **자기 트리의
  빈 `runtime/`** 으로 조용히 풀린다.
- 환경변수로 공유 경로를 넘기는 길도 막혀 있다: `load_dotenv()` 는 "실 백엔드(DACON)만 호출한다 —
  테스트는 `.env` 없이도 전부 통과해야 한다"는 제약을 달고 있어 CPU 진입점에 `.env`가 실리지 않는다.

코디네이터가 dispatch 시 spec에 경로를 박아 넘긴다. 공유 상태를 새로 만들지 않는다.

### 3.2 읽기는 공유, 쓰기는 자기 트리

워커는 main 체크아웃의 `runtime/` 을 **읽기만** 한다. ŝ 덤프와 ckpt는 불변 아티팩트이고,
`np.load(..., mmap_mode="r")` 이므로 워커 수가 늘어도 359 MB가 복제되지 않는다. 실질 한계는
GPU가 아니라 CPU 코어와 zip 쓰기 I/O다.

결과(zip, 진단 JSON)는 **자기 워크트리 안**에 쓴다. 워크트리끼리도, main과도 경합이 없다.

### 3.3 새 불변식 — 워크트리에 `runtime/registry.jsonl` 을 만들지 않는다

그 파일의 존재가 곧 실험 게이트의 센티넬이다. 한 번 생기면 그 트리의 게이트가 **영구 해제**된다.
워커가 `runtime/` 하위 디렉터리를 만드는 것은 무방하나 이 파일만은 안 된다. 규율로 두지 않고
§4에서 검사로 고정한다.

### 3.4 레지스트리는 코디네이터 독점

1. 코디네이터(main)가 `exp.py new` 로 선보고 → `report_id` 발급
2. `report_id` 와 입력 경로를 spec에 실어 `dispatch --inject`
3. 워커는 계산만 하고 `worker_done --outcome` 에 진단 JSON을 실어 반환 — **`exp.py` 를 부르지 않는다**
4. 코디네이터가 `exp.py result` 로 기록

`report_id = len(records)` 포크 경로가 구조적으로 존재하지 않게 된다. `registry.locked()` 는
main 내부의 sub-agent 동시성 때문에 그대로 필요하다.

### 3.5 provenance

현재 `new_report()` 가 쓰는 레코드에는 **커밋도 브랜치도 없다.** 단일 체크아웃에서는 넘어갔지만,
병렬화하면 "코디네이터는 `main` 에 앉아 기록하는데 코드는 워커 브랜치"가 되어 기록이 조용히
어긋난다. custflow가 MLflow에서 같은 계열의 사고를 겪고 `provenance_note` 로 손backfill한 전례가
있다.

- 선보고 스키마에 소스 브랜치/커밋 필드를 **optional로** 추가한다. 기존 20건은 그대로 둔다.
- 워커가 자기 트리의 `git rev-parse HEAD` 와 브랜치를 `worker_done` 에 실어 보내고, 코디네이터는
  **그것을** 기록한다. 자기 HEAD를 쓰지 않는다.
- 워커는 **커밋된 상태에서** 실행한다. 더티 트리로 돌면 기록된 커밋이 실행 코드가 아니게 된다.

## 4. 게이트 등급 분리

`GUARDED` 단일 목록을 사유별로 쪼갠다. 훅 계약(`enforcement.md`)이 "deny 메시지는 왜 걸렸는지·
대안·탈출구를 말해야 한다"를 요구하는데, 지금은 사유가 다른 6개가 한 문구를 공유한다.

| 분류 | 스크립트 | 사유 | 워크트리에서 |
|---|---|---|---|
| `REGISTRY_WRITERS` | `exp.py` | `report_id = len(records)` 포크 | deny |
| `EXCLUSIVE` | `train_level` · `train_structure` · `infer_decomposed` · `dacon_submit` | GPU 8 GB / 제출 슬롯 | deny |
| **해제** | `probe_level` | 읽기 전용, `runtime/` 에 쓰지 않음 | **허용** |
| **비대상** | 새 CPU 진입점 | 자기 트리에만 씀 | 허용 |

`probe_level` 해제의 근거: `mmap_mode="r"` 로 읽고 결과를 stdout JSON으로만 뱉는다. 워크트리에
캐시가 없으면 `np.load` 가 **시끄럽게** 실패한다 — 조용한 오염 경로가 없다. 게이트가 막던 것은
레지스트리 포크인데 이 스크립트에는 그 경로가 아예 없다.

**탈출구를 좁힌다.** `ACS_RUNTIME_EXEMPT` 는 `EXCLUSIVE` 에만 적용하고 `REGISTRY_WRITERS` 에는
적용하지 않는다. 지금은 6개 전부에 열려 있어, 한 번 뚫으면 센티넬 파일이 생겨 그 트리의 게이트가
영구 해제된다. `exp.py` 는 "main에서 실행"이라는 대안이 항상 실재하므로 막아도 막다른 길이
아니다. 이로써 §3.3의 불변식이 규율이 아니라 검사가 된다.

## 5. A2A 잔재 정리

`No protocol layer` 절은 2026-07-30에 걷어낸 A2A/MCP 레이아웃의 이력으로 쓰여 있다. A2A는
레거시가 되었으므로 절을 삭제한다. 삭제 대상은 정확히 세 곳이다:

- `.agents/rules/architecture.md` → `## No protocol layer`
- `tests/test_config.py::test_no_a2a_leftovers` — 금지 목록의 `executor` 가 현재 에이전트 레인
  이름이라, 나중에 executor 설정이 필요해지면 옛 잔재 테스트가 엉뚱하게 막는 잠복 충돌도 함께
  사라진다
- `config.yaml` 첫 줄 "에이전트 포트·mock 스위치는 A2A 구조와 함께 제거됨" 주석

**잃는 것을 기록해 둔다**: 이 절은 "에이전트 간 통신을 위한 서비스·서버·스택을 세우지 않는다"의
유일한 성문 브레이크였다. 삭제 후 그 자리를 메우는 것은 §7의 "상태를 만들지 않는다"는 결정이다.

## 6. 검증

기존 관용구를 따른다 — **오프라인(GPU/캐시 불필요, 합성 데이터)으로 계약을 고정한다**
(`tests/test_infer_decomposed.py` 가 이미 그 전제로 돈다).

- **경로 등가성** — 합성 캐시와 최소 모델로, ① GPU 경로 한 방과 ② ŝ 덤프 → CPU 재조립이
  **바이트 동일** zip을 내는지. 두 경로가 같은 조립 함수와 같은 인코더를 쓰므로 바이트까지
  같아야 하며, 이것이 단일화의 실질적 보증이다.
- **인코더 왕복** — 새 `encode_png_gray8` 의 출력을 기존 `decode_png_gray8` 이 원본 배열로
  복원하는지. cv2가 설치된 환경에서는 `pytest.importorskip("cv2")` 로 cv2 디코드와도 교차
  검증한다 (`test_submission.py::test_decode_matches_cv2_when_available` 의 전례).
- **덤프 왕복 무손실** — float32 저장·로드가 ŝ를 비트 단위로 보존하는지. §2.1에서 float16을
  버린 근거를 테스트로 고정한다.
- **게이트** (`test_block_runtime_commands.py` 에 must-block / must-pass 양쪽):
  `probe_level` 이 레지스트리 없는 트리에서 통과 · `exp.py` 는 `ACS_RUNTIME_EXEMPT` 가 있어도
  여전히 deny · 나머지 4개는 탈출구로 통과 · 새 CPU 진입점은 비대상.
- **레지스트리 스키마** — provenance optional 필드 추가 후 기존 20건이 그대로 로드·렌더되는지
  (`test_registry.py`).

**오프라인으로 잡히지 않는 것 — 실제 레시피 회귀.** 합성 등가성은 "두 경로가 같다"만 증명한다.
"새 경로가 과거 채택 레시피를 재현한다"는 실제 ckpt와 캐시가 필요하고 그것은 main에만 있다.
따라서 테스트가 아니라 **착지 시점의 1회 증거**로 잡는다: EXP-019 레시피(`--level-smooth 9`)를
기존 CLI로 한 번, 새 2단계로 한 번 돌려 비교한다. 비교 기준은 **zip의 sha256이 아니라
25,988장의 픽셀 일치**다 — §2.3에서 인코더가 cv2에서 stdlib으로 바뀌므로 바이트는 과거와
달라지고, 채점되는 것은 픽셀이기 때문이다. 두 zip을 `decode_png_gray8` 로 풀어 배열이
전부 같은지 확인하고, 아울러 `verify_submission()` 이 양쪽 모두 통과하는지 본다. 한 장이라도
다르면 착지를 중단한다.

## 7. 제출 슬롯 선별

사전 선별 지표는 이미 있고, 축마다 강도가 다르다.

| 축 | 인자 | 선별 지표 | 도메인 정합 |
|---|---|---|---|
| 레벨 | `k` · `a` · `level_source` | real train + `site_split` 홀드아웃 정확도 | **real→real** |
| 구조 | `τ` | sim 홀드아웃 | sim — 약한 신호 |
| 최종 | 전부 | 리더보드 | 유일한 판정 |

레벨 축의 사전 선별은 정당하다 — `real_group_label` 은 레지스트리 기준 실측 GT이고, `k=9` 가
실제로 그렇게 골라졌다(`smooth_levels` 독스트링: k=9에서 0.9806 → 0.9975, k=31은 0.9897로
경계 손상 때문에 되레 나빠진다). 다만 **선별이지 판정이 아니다**: real은 런 2,836개, test는
1,046개로 런 길이가 달라 최적 k가 그대로 옮겨가지 않는다.

- 워커는 zip을 **만들되 제출하지 않는다.** `dacon_submit` 은 `EXCLUSIVE` 라 워크트리에서 deny다.
- 워커는 `verify_submission()`(파일 수 25,988 · 이미지별 max ∈ {140,150,160,170} 하드 프리체크)을
  자기 트리에서 돌려 깨진 zip을 **슬롯을 쓰기 전에** 거른다. 이 함수는 GUARDED 밖이다.
- 코디네이터가 순위를 보고 상위 1개만 제출하며, 선별 근거를 레지스트리에 기록한다.

**선보고 단위: 스윕 하나 = 선보고 하나.** EXP-010이 "AdaBN 조합 3-arm", EXP-015가 "2가설"을 한
항목으로 기록한 전례를 따른다. `exp.py result` 가 기본으로 기존 `val` 에 **병합**하므로 arm별
결과를 순차로 쌓을 수 있고, 스키마를 새로 만들 필요가 없다.

## 8. 이 변경이 증명하지 못하는 것

- **점수가 오른다는 것.** 이 변경은 탐색을 가능하게 할 뿐, 어떤 `k` 나 `a` 가 리더보드를 올리는지는
  말하지 않는다. 판정은 여전히 리더보드뿐이고 슬롯은 유한하다.
- **워커 N개가 실제로 붙는다는 것.** `orca-parallel.md` 는 "worktree 간 동작은 미측정"으로 남겨
  두었다. 이 스펙은 워커가 돌 **자리**를 만들 뿐, Orca가 워크트리를 가로질러 잘 동작하는지는
  별도 측정 대상이다.

## 9. 범위 밖

- **오케스트레이터의 스케줄링 규약** — 계획 수립, GPU/비GPU 분류, dispatch 순서. 다음 사이클.
  지금 쓰면 검증할 병렬 작업이 아직 없는 문서가 된다.
- **GPU 리스·큐** — 상태를 만들지 않기로 했다. 직렬화는 "코디네이터가 GPU 태스크를 둘 동시에
  dispatch하지 않는다"는 규율로 유지한다.
- **학습(`train_*`) 병렬화** — 8 GB 카드 하나라 불가.
- **기록소의 wandb 전환** — `2026-09-13-wandb-registry-design.md`. §4의 게이트가
  `runtime/registry.jsonl` 의 존재에 걸려 있으므로, 그 전환은 **대체 센티넬을 먼저 설계해야**
  한다. 놓치면 게이트가 조용히 무효가 된다.
- **`runtime/submission_work/` 의 평평한 PNG 잔여물** — 코드는 `zip_path.stem` 하위에 쓰는데
  최상위에 PNG가 남아 있다. 병렬 덮어쓰기 사고를 고치기 전의 잔재로 보인다. 착지 전에 확인은
  하되 정리는 별건이다.
